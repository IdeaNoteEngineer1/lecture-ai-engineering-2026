## 演習

- 講座に固有の質問（宿題の3レベル）へのモデルの回答：
	- `gemini-3.5-flash-lite` は、3段階の課題を一般的な「基礎・応用・発展」などと説明し、各段階の課題例を挙げていました。回答では講座によって定義が異なる可能性にも触れ、教材や資料の確認を勧めていました。
	- `gemini-3.1-flash-lite` も、実装難易度や学習段階など一般的な分類を複数提示し、講座固有の正確な定義は教材で確認するよう勧めていました。どちらのモデルも、講座固有の定義を特定できず、一般論を推測として回答していました。
- 用語集の正しい意味と比べて気づいたこと：
	- [用語集](../../data/glossary.json)では「基礎（講義内容の確認）」「実装（自分でコードを書く）」「発展（調査や試行）」の3段階で、どれか1つに取り組めば宿題は完了です。

## 宿題

- 取り組んだレベル：発展
- やったこと：
	- `time.perf_counter()` で `generate_content` 呼び出し直前から応答が返るまでを測り、画面表示時間を含めないようにしました。`response.usage_metadata` から入力・出力・思考・合計トークン数を取得し、未取得値は `null`（通常表示では「取得できず」）にしました。`--json` は比較用データだけを標準出力へ出します。
	- `scripts/benchmark_lecture01.py` から現在の Python 環境で `app.ask --json` を子プロセス起動し、モデルごとに直列で比較しました。子プロセス全体の時間と、`ask.py` が測った API 呼び出し時間は別の値として保存しています。

	- 元実験は `gemini-3.5-flash-lite` と `gemini-3.8-flash`、同じ2問を各3回ずつの計12試行で、子プロセスの上限は120秒でした。[実験結果](results/20261026T065035.533354Z/)（[summary.md](results/20261026T065035.533354Z/summary.md)、[metadata.json](results/20261026T065035.533354Z/metadata.json)、[trials.jsonl](results/20261026T065035.533354Z/trials.jsonl)）

- 気づき・疑問：
	- 今回の標本では、3.5 Flash-LiteのAPI時間平均と出力トークン平均は、両質問とも3.1 Flash-Liteより小さくなりました。一方、回答の長さも異なります。各条件3回ずつの小さな標本で、実験した時間帯も異なるため、この結果だけからモデル固有の速度や総合性能の優劣は断定できません。特に3.1 Flash-LiteのLoRA質問はAPI時間が3.726〜15.853秒とばらつきました。
	- 回答の内容・正確さは、実際の回答ログを用語集と照らして速度とは分けて評価します。今回の「3レベル」回答は一般論を多く含み、用語集の「基礎・実装・発展」および「どれか1つで完了」という定義を正確に再現していません。
	- APIの利用枠にはRPM（1分あたりのリクエスト数）、TPM（1分あたりのトークン数）、RPD（1日あたりのリクエスト数）などの上限があります。20秒間隔は短時間の集中を避ける工夫ですが、日次上限の回避や成功を保証するものではありません。今回の保存ログでは3.8 Flashの失敗区分はタイムアウトで、HTTPステータスは記録されていません。原因をレート制限と断定できません。
	- ベンチマークスクリプト独自の再試行はありません。Google Gen AI SDK内部の再試行設定・動作は確認していません。
